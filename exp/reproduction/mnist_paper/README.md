## Protocol
- In-distribution: 1000 images from the MNIST **test** split (100 per class, seed 0). The paper evaluates on a held-out set of 1000; note the repo's own `--sample` evaluates on 3000 *training* images instead.
- OOD: EMNIST `balanced`, classes 0-19 (digits 0-9 + letters A-J), 300 per class, as in `MNISTRunner.sample()` with `in_sample: false`.
- One posterior sample z ~ q(z|x) per image; one posterior predictive sample x ~ p1(x|z) per z.
- log p(x|z): `vt.log_prob(x, z, 0, priory)` (Hutchinson trace, adjoint ODE), computed in the logit-transformed space the model is trained in (`LogitTrans(0.01, 0.99)`), as in the code.
- log p(z|x): continuous — `LightningModule.sample_and_log`; mixture — `rt.log_prob(logits0, x, z0)` as in the validation loop.
- SSIM: posterior predictive vs. input, pixel space, torchmetrics defaults (same preprocessing as `generate_img`). 'SSIM (code protocol)' is the value returned by `generate_img` itself (first image of each class, 7 samples each).
- Vendi: `vendi.score_dual(z, normalize=True)` on the posterior samples z, as the repo's MNIST test code computes it (this is the quantity in the paper's Table 2). 'Vendi x' is the same score on the posterior-predictive images (pixel space), which the paper does not report.
- `table_train_protocol`: NMI / ARI / Vendi / softNMI / log p(z|x) recomputed on 3000 MNIST **training** images (300 per class), the set the repo's `--sample` command uses. The paper's Vendi values fit this set size rather than the 1000 held-out images of its captions.
- `table_ablations`: runs that differ from the paper config in one setting the paper does not state explicitly (marked INFERRED / PAPER in the config).
- NMI/ARI: continuous — `test_plot_latent` (KMeans on z, k=10 / k=20 for OOD); mixture — `test_plot_latent` (argmax of q(xi|x)) and `soft_nmi`.
- VAE and Mixture-SVAE: our implementations (`baselines/vae.py`, `baselines/mixture_svae.py`), not the authors' code; trained and evaluated by the authors' continuous / mixture LightningModules with the loss replaced by the (mixture) negative ELBO. Choices the paper does not state are in the `vae:` / `mixture_svae:` sections of the config.
- SFA w/Deterministic: named in the paper but not implemented in the repository; here it is the authors' SFA with z = posterior mean in training and evaluation (`flow.deterministic`).
- Not reproducible from this repo: VampVAE, Latent FM, Latent FM (VAE) (no code), and the corresponding figure panels.

## Metrics

↑ = higher is better, as marked in the paper; no MNIST/EMNIST metric is lower-is-better. How to read each one:

- **log p(x|z) ↑**: higher is better. Log-likelihood (nats) of the test image under the decoder, given z ~ q(z|x), in the logit-transformed pixel space the code trains in. Compare only within one model family: a Gaussian decoder (VAE, Mixture-SVAE) can score very high from tight variances on the constant background pixels.
- **log p(z|x) ↑**: higher = more concentrated posterior (the paper marks it ↑). Log density (nats) of q(z|x) at its own sample. Capped by each model's std floor (per latent dimension: about 10.1 nats for a 1e-5 floor, 12.4 for 1e-6, 17.0 for 1e-8), and a posterior collapsed onto that floor scores highest, so higher is not automatically better. The paper's 793.26 for SFA is 64 x 12.4: a 64-dim posterior sitting on a 1e-6 floor.
- **Vendi ↑**: higher = more diverse latent samples z ~ q(z|x) (effective number of distinct directions; at most the latent dimension). This is what the repository's MNIST test code reports as Vendi (`vendi.score_dual(z, normalize=True)`), and what the paper's Table 2 reports: its VAE value, 63.29, is what 3000 draws from a 64-dim standard normal give (63.33). The value depends on the number of images.
- **Vendi x ↑**: diversity of the posterior-predictive images (higher = more diverse). Not a quantity the paper's tables report. Noisy or unrelated samples also score high, so read it together with SSIM.
- **SSIM ↑**: higher is better (0 to 1): structural similarity between each test image and its posterior-predictive sample.
- **NMI (OOD) ↑**: higher is better (0 = no relation to the labels, 1 = perfect). Agreement of the latent clustering with the labels: KMeans on z with k given (k = 10; 20 for OOD). First value MNIST, in parentheses EMNIST (out of distribution).
- **NMI ↑**: higher is better (0 = no relation to the labels, 1 = perfect). Agreement of argmax q(xi|x) with the digit labels.
- **ARI (OOD) ↑**: higher is better (0 = chance level, can be negative; 1 = perfect). First value MNIST, in parentheses EMNIST (out of distribution).
- **ARI ↑**: higher is better (0 = chance level, can be negative; 1 = perfect).
- **softNMI ↑**: the paper marks it ↑, but with the authors' soft_nmi higher is NOT reliably better: a perfect clustering scores 0.750, an uninformative uniform q(xi|x) 0.600, and all images in one component 0.800. Use NMI / ARI to judge clustering.
- **SSIM (code protocol) ↑**: higher is better (0 to 1). SSIM as returned by the authors' generate_img: first test image of each digit, 7 posterior-predictive samples each.
- **checkpoint epoch**: epoch of the evaluated checkpoint; best = lowest validation loss.
